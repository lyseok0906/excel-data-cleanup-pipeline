# Validation tooling

Stdlib-only Python (no third-party dependencies, no network access required). Run from anywhere; paths default relative to this script's location.

```bash
# Regenerate validation_10_v2.csv from validation_10.csv
python migrate_schema.py

# Build the A0-Phase2 40 new sites (Excel, Personal Finance, Home/DIY & Food,
# Product Review) directly in V2 canonical schema, and concatenate with the
# existing 10 into validation_50_v2.csv
python build_a0_phase2.py

# Run the Protocol V2 Validation Gate against any CSV (defaults to ../validation_10_v2.csv)
python run_gate_v2.py
python run_gate_v2.py ../validation_50_v2.csv --report ../gate_report_50.txt
# exit code 0 = all checks passed, 1 = at least one FAIL

# Run the regression/self-test suite
python -m unittest test_validation_tooling.py -v

# Generate an automated, dataset-neutral summary (row/category/stratum/
# evidence-tier distributions, UNKNOWN rates, field completion, etc.)
python summarize_dataset.py ../validation_50_v2.csv --out ../summary_50.txt

# (Re)build the Domain Registry (research/blog-monetization/registry/domain_registry.csv),
# seeding COMMITTED rows from the current Study A cumulative CSV. Pass
# --pilot-csv <path to blog-monetization-100/sites.csv> to also seed the
# 97 unique prior-pilot domains as EXCLUDED_PRIOR_PILOT (that file is not
# present in every checkout -- see the module docstring for details).
python build_domain_registry.py [--a0-csv ../validation_50_v2.csv] [--pilot-csv ...]

# Verify the single-coordinator wave state machine end-to-end against
# SYNTHETIC placeholder domains only (never real 950-site research; see
# schema_extend.py / wave_coordinator.py below).
python wave_coordinator.py --demo
```

- `domain_utils.py` — registrable-domain (eTLD+1) canonicalization, used by `run_gate_v2.py` for duplicate detection. Embeds a curated list of common multi-label public suffixes (co.uk, com.au, etc.) since this environment has no network/dependency access to a full Public Suffix List package (e.g. `tldextract`). See the module docstring for the known limitation and the drop-in replacement path if `tldextract` becomes available later. **Status as of the latest engineering patch (2026-09-17, GPT review of commit 13a383d): still blocked, re-confirmed.** Both the cloud sandbox (`pip install tldextract`, `pip download`, direct PyPI access -- all 403 via org egress policy) and the user's local Windows machine (`device_bash` still failing to start due to the September 8 Windows-update Plan9-mount issue) remain blocked. Per explicit user instruction, the manual suffix list was **not** expanded further. `test_validation_tooling.py::test_full_psl_blogspot_subdomains_should_be_distinct` now states the DESIRED behavior (`foo.blogspot.com != bar.blogspot.com`) and is marked `@unittest.expectedFailure` -- it currently, correctly, fails (shown as "expected failure" in test output, not a silent pass), and the decorator must be removed once Full PSL is implemented (an unexpected pass would then flag that removal is overdue). This replaces a prior version of the test that asserted the wrong behavior as a "PASS". A full PSL swap-in requires either a future environment with real network/pip access, or the user pinning an official PSL snapshot file into the repo from their own machine -- `registrable_domain()`'s signature is kept stable for that swap.
- `schema_extend.py` — single source of truth for the Study A production-schema fields Protocol V2 Section 2 always specified but that were missing from the actual canonical schema: `category`, `sub_category` (reserved, UNKNOWN for now), `as_of_date` (ISO, mandatory), and the `content_scale_proxy_value/_method/_evidence/_source_url/_note` evidence-bearing group (UNKNOWN for all current 50 rows -- no new research was performed to populate it). **`CATEGORY_ENUM` is now the FINAL 11-value production taxonomy** (latest patch, GPT review of commit 13a383d, Item 3): the original 100-site pilot's 10 categories, with "Excel/Spreadsheet/Productivity" split into "Productivity / PKM" and "Excel / Spreadsheet" (A0 already executed them as separate batches). Also exposes `PRIOR_PILOT_CATEGORY_MAP` (maps the pilot study's own raw category strings to the production taxonomy, used only for `EXCLUDED_PRIOR_PILOT` registry rows -- one pilot bucket, `Excel/Spreadsheet/Productivity`, keeps an explicit legacy pass-through value rather than being force-split without new research), `DOMAIN_CATEGORY_OVERRIDES` (un-merges A0-Phase2's old "Home / DIY & Food" batch into "Food / Recipe" x5 / "Home / DIY" x5 using each site's already-recorded `primary_niche`, no new research), `CATEGORY_BATCH_PLAN`, and `extend_rows_with_production_schema(rows, start_index)`, called from both `migrate_schema.py` and `build_a0_phase2.py`. The production schema is 65 columns total (see research_protocol_v2.md Section 7-D-1 for the full list).
- `evidence_harden.py` — shared post-processing pass applied to every generated row in both generator scripts below, enforcing: (1) a non-UNKNOWN value must carry a non-UNKNOWN evidence tier; (2) evidence in {A, B, C} must carry a real dedicated `_source_url` -- no auto-backfill for ANY tier, including C; (3) evidence == D must carry a non-empty `_note` -- no auto-fill; (4) **new, GPT review of commit 13a383d Item 1** -- `content_scale_proxy_value != UNKNOWN` requires `content_scale_proxy_method != UNKNOWN` too. Raises `EvidenceHardenError` on any violation, so the generator script must supply the real URL/reasoning/method by hand. **`content_scale_proxy` is now included in `ALL_GROUPS`** (11 evidence-bearing groups total, up from 10 -- it had been added to the canonical schema but never wired into `ALL_GROUPS`, so it was silently skipped by every consumer of that list). New `verify_group_coverage(fieldnames)` structurally checks that every `*_evidence` column in a schema's field list belongs to exactly one `ALL_GROUPS` entry (no missing, no duplicated) -- this is what would have caught the content_scale_proxy omission automatically; it's now Gate Section 14. This module performs no research and invents nothing -- it is purely a consistency check.
- `migrate_schema.py` — reproducible migration from the raw A0-Phase1 schema (`validation_10.csv`) to the Protocol V2 canonical schema (`validation_10_v2.csv`). All provenance-URL backfills and the traffic_scope-aware `traffic_tier` rule are baked into this script (not applied as one-off patches afterward). Also exposes `FIELDNAMES` (65 columns total) and `traffic_tier_for()`, reused by `build_a0_phase2.py`. Calls `schema_extend.extend_rows_with_production_schema(rows, start_index=0)` at the end of `build_rows()`; each individual `row()` call also seeds placeholder UNKNOWN `content_scale_proxy_*` fields before its own `evidence_harden.harden_row()` call, since that check now needs those fields to already exist (they're only bulk-assigned by `schema_extend` afterward). `SOURCE_URL_OVERRIDES` and inline UNKNOWN-revert tuples encode the reviewed KEEP/REVERT decisions for the previously-auto-backfilled C-tier citations.
- `build_a0_phase2.py` — builds the A0-Phase2 40 new-site rows directly in the V2 canonical schema (not a migration -- these are new research entries) and concatenates them with the existing 10 into `validation_50_v2.csv`. All facts/URLs were gathered by dedicated research passes before this script was written; the script only assembles and validates structure (enforces Rule #8, computes `traffic_tier` from `traffic_scope`, checks for column/row-order mismatches and duplicate domains within the batch, excluding `schema_extend.ALL_NEW_FIELDNAMES` from the per-row completeness check since those are only added by the later batch-level `schema_extend` call). Calls `schema_extend.extend_rows_with_production_schema(rows, start_index=10)` and runs all rows through `evidence_harden.harden_rows()` before writing. As of the pre-950 hardening round, `traffic_scope` reflects domain *structure* (content-publisher vs. SaaS/app-mixed vs. subdirectory-estimate), not merely whether a traffic number was found -- see research_protocol_v2.md Section 3-6 -- and `revenue_value` is always either `UNKNOWN` or a single clean structured figure, never descriptive/compound/acquisition text (see Section 7-C item 3). The last pre-950 patch added real D-tier reasoning notes (previously empty) for 5 `own_product`/`course_or_community` fields.
- `run_gate_v2.py` — the Protocol V2 Validation Gate (research_protocol_v2.md Section 7). Accepts an optional CSV path argument; defaults to `../validation_10_v2.csv`. Runs **15 sections** (value-requires-evidence directional check, D-tier-requires-note check, `revenue_value` format check, `category` enum validation, mandatory ISO `as_of_date`, `content_scale_proxy_evidence` checks folded into the existing provenance/note/value-requires-evidence/Rule-8 checks, plus -- new, GPT review of commit 13a383d -- Section 14 evidence-group coverage check (`check_group_coverage`, wraps `evidence_harden.verify_group_coverage`) and Section 15 `content_scale_proxy_value` requires `content_scale_proxy_method`) and its final summary line is dataset-neutral (`VALIDATION GATE PASS -- rows=N`).
- `summarize_dataset.py` — automated, dataset-neutral summary generator. Computes row count, `category` distribution (the actual closed-enum field, now the final 11-value production taxonomy, **not** `primary_niche`; `primary_niche` is reported separately as free-text reference-only detail with distinct/singleton counts), sampling_stratum/traffic_scope/traffic_tier distributions, `is_contrast_case` counts (kept explicitly separate from `sampling_stratum == "Contrast Cohort"` counts -- these are different axes), per-field UNKNOWN rate and completion rate, and the evidence-tier distribution (self-check: `N evidence-bearing fields x N rows`, now **11 × 50 = 550** since `content_scale_proxy` joined `ALL_GROUPS`, printed alongside the actual count so an arithmetic mismatch is structurally impossible). No code changes were needed here for the content_scale_proxy fix -- it reads `evidence_harden.ALL_GROUPS` dynamically. Replaces all manual/hand-typed aggregation in reports going forward.
- `build_domain_registry.py` — Domain Registry builder/tooling for the future wave-based 950-site expansion. Maintains `research/blog-monetization/registry/domain_registry.csv` (one row per canonical root domain, `status` in {EXCLUDED_PRIOR_PILOT, RESERVED, COMMITTED, REJECTED}). State machine: `IMMUTABLE_STATUSES = {EXCLUDED_PRIOR_PILOT, COMMITTED}` plus a shared `_transition()` helper make `commit_domains()`/`reject_domains()` raise `RegistryStateError` for a domain not in the registry, a domain in an immutable status, a domain not currently `RESERVED`, or a `batch_id` mismatch. **`_transition()` was hardened again (GPT review of commit 13a383d, Item 5-D) to validate ALL domains in a call before mutating ANY of them** -- previously, a partially-invalid list of domains could leave earlier, valid domains half-transitioned before the loop hit the invalid one and raised. The seed-time A0/prior-pilot registrable-domain overlap check is a hard `FAIL`/non-zero exit. **`category` seeding was fixed (Item 4)**: `_seed_from_study_csv()` now takes `category_field`/`category_map` parameters -- A0/COMMITTED rows read the real production `category` column, and prior-pilot/EXCLUDED_PRIOR_PILOT rows read the pilot's own broad `category` column translated via `schema_extend.PRIOR_PILOT_CATEGORY_MAP` -- both previously read free-text `primary_niche` instead. New `validate_registry_categories()` hard-FAILs if any row's category isn't a legitimate mapped value. **Merge logic split into `load_master_rows()` / `compute_merge()` (pure, in-memory, no write) / `write_rows_csv()`** (Item 5) so a caller (see `wave_coordinator.py`) can Gate the merged result BEFORE writing it to disk; `merge_wave_into_master()` remains as a back-compat wrapper composing all three in one call. Currently seeds the 50 A0-cumulative domains as COMMITTED and the prior 100-site pilot's 97 unique domains as EXCLUDED_PRIOR_PILOT via `--pilot-csv` (147 rows total, 0 overlap, categories validated).
- `wave_coordinator.py` — single-coordinator wave orchestrator for the future 950-site expansion. Only this module is expected to call registry-mutating functions; parallel research workers never touch the registry directly, they only research already-RESERVED domains and hand back plain row dicts. **`run_wave()`'s transaction order was fixed (GPT review of commit 13a383d, Item 5)**: the previous version wrote registry status=COMMITTED BEFORE merging into the master file, so a merge failure could leave the registry claiming COMMITTED while the master dataset never actually gained the row. The new order is: RESERVE → research → wave Gate (the wave's own rows) → validate the merge in memory only, no write (`build_domain_registry.compute_merge()`) → Gate the FULL merged row set (existing master + wave) → **only if both Gates passed**, write the master file (`write_rows_csv()`) → **only after that write succeeds**, `commit_domains()` and save the registry. Either Gate failing raises `WaveAbortedError`, leaves the domains RESERVED (not committed, not rejected), and leaves the master file completely untouched. `python wave_coordinator.py --demo` exercises the full state machine end-to-end against 3 SYNTHETIC placeholder domains in a temp registry/master file. This round performs no real 950-site research -- `--demo` is the only supported CLI mode.
- `test_validation_tooling.py` — regression tests, now **41/41 passing (1 expected failure)**. 12 from the GPT review of commit `40732be` (Section 7-B) + 16 from the "remove auto-fabrication" patch (Section 7-D) + 13 new from the latest patch (Section 7-E, GPT review of commit 13a383d): `content_scale_proxy` group-coverage tests (in `ALL_GROUPS`, 11 groups total, `verify_group_coverage` catches a missing/duplicated field, clean against the real schema), `content_scale_proxy_value`-requires-`_method` (raises / passes / Gate check both ways), 4 new wave-transaction tests (`TestWaveTransactionOrdering`: A = merge failure leaves registry RESERVED and master untouched, B = merged-master Gate failure leaves registry RESERVED and master untouched even though the wave's own rows were clean, C = all-pass commits the registry and merges the master, D = `commit_domains()` validates every domain before mutating any, so a partially-invalid list mutates nothing), and the Full-PSL test replaced with a `@unittest.expectedFailure`-marked desired-behavior test (`foo.blogspot.com != bar.blogspot.com`) instead of one that asserted the wrong behavior as a pass.
