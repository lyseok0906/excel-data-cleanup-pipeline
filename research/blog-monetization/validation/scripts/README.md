# Validation tooling

Stdlib-only Python (no third-party dependencies, no network access required). Run from anywhere; paths default relative to this script's location.

```bash
# Regenerate validation_10_v2.csv from validation_10.csv
python migrate_schema.py

# Build the A0-Phase2 40 new sites (Excel, Personal Finance, Home/DIY & Food,
# Product Review) directly in V2 canonical schema, and concatenate with the
# existing 10 into validation_50_v2.csv
python build_a0_phase2.py

# Run the Protocol V2 Validation Gate against any CSV (defaults to ../validation_10_v2.csv)
python run_gate_v2.py
python run_gate_v2.py ../validation_50_v2.csv --report ../gate_report_50.txt
# exit code 0 = all checks passed, 1 = at least one FAIL

# Run the regression/self-test suite
python -m unittest test_validation_tooling.py -v

# Generate an automated, dataset-neutral summary (row/category/stratum/
# evidence-tier distributions, UNKNOWN rates, field completion, etc.)
python summarize_dataset.py ../validation_50_v2.csv --out ../summary_50.txt

# (Re)build the Domain Registry (research/blog-monetization/registry/domain_registry.csv),
# seeding COMMITTED rows from the current Study A cumulative CSV. Pass
# --pilot-csv <path to blog-monetization-100/sites.csv> to also seed the
# 97 unique prior-pilot domains as EXCLUDED_PRIOR_PILOT (that file is not
# present in every checkout -- see the module docstring for details).
python build_domain_registry.py [--a0-csv ../validation_50_v2.csv] [--pilot-csv ...]

# Verify the single-coordinator wave state machine end-to-end against
# SYNTHETIC placeholder domains only (never real 950-site research; see
# schema_extend.py / wave_coordinator.py below).
python wave_coordinator.py --demo
```

- `domain_utils.py` — registrable-domain (eTLD+1) canonicalization, used by `run_gate_v2.py` for duplicate detection. Embeds a curated list of common multi-label public suffixes (co.uk, com.au, etc.) since this environment has no network/dependency access to a full Public Suffix List package (e.g. `tldextract`). See the module docstring for the known limitation and the drop-in replacement path if `tldextract` becomes available later. **Status as of the last pre-950 engineering patch (2026-09-17, commit 8dffb08 GPT follow-up): still blocked, re-confirmed.** Both the cloud sandbox (`pip install tldextract`, `pip download`, direct PyPI access -- all 403 via org egress policy) and the user's local Windows machine (`device_bash` still failing to start due to the September 8 Windows-update Plan9-mount issue) were re-attempted and remain blocked. Per explicit user instruction, the manual suffix list was **not** expanded further and this is reported as a standing blocker. `test_validation_tooling.py::test_KNOWN_LIMITATION_blogspot_subdomains_incorrectly_collapse` intentionally asserts the current wrong behavior (`foo.blogspot.com` == `bar.blogspot.com`) so a future full-PSL swap-in will fail that test loudly and prompt an update, rather than silently changing behavior. A full PSL swap-in requires either a future environment with real network/pip access, or the user pinning an official PSL snapshot file into the repo from their own machine -- `registrable_domain()`'s signature is kept stable for that swap.
- `schema_extend.py` — (new, last pre-950 engineering patch) single source of truth for the Study A production-schema fields Protocol V2 Section 2 always specified but that were missing from the actual canonical schema: `category` (closed 5-value enum, kept separate from the free-text `primary_niche`), `sub_category` (reserved, UNKNOWN for now), `as_of_date` (ISO, mandatory), and the `content_scale_proxy_value/_method/_evidence/_source_url/_note` evidence-bearing group (UNKNOWN for all current 50 rows -- no new research was performed to populate it). Exposes `CATEGORY_ENUM`, `CATEGORY_BATCH_PLAN` (the fixed, already-known batch-to-category/date mapping), and `extend_rows_with_production_schema(rows, start_index)`, called from both `migrate_schema.py` and `build_a0_phase2.py`. The production schema is now 65 columns total (see research_protocol_v2.md Section 7-D-1 for the full list).
- `evidence_harden.py` — shared post-processing pass applied to every generated row in both generator scripts below. **Rewritten in the last pre-950 engineering patch (2026-09-17) to remove two auto-fabrication behaviors**: it used to auto-backfill a guessed homepage URL for C-tier evidence missing a `_source_url`, and auto-insert a generic placeholder note for D-tier evidence missing a `_note`. Both are now hard failures instead: (1) a non-UNKNOWN value must carry a non-UNKNOWN evidence tier (unchanged, directional complement of Rule #8); (2) evidence in {A, B, C} must carry a real dedicated `_source_url` -- no auto-backfill for ANY tier now, including C; (3) evidence == D must carry a non-empty `_note` -- no auto-fill. Raises `EvidenceHardenError` in all three cases, so the generator script must supply the real URL/reasoning by hand (see `migrate_schema.py`'s `SOURCE_URL_OVERRIDES` / literal UNKNOWN-revert tuples and `build_a0_phase2.py`'s added D-tier reasoning notes for how the existing 50-row dataset's 26 KEEP + 9 REVERT (C-tier) and 9 real-reasoning (D-tier) corrections were applied). This module now performs no research and invents nothing -- it is purely a consistency check.
- `migrate_schema.py` — reproducible migration from the raw A0-Phase1 schema (`validation_10.csv`) to the Protocol V2 canonical schema (`validation_10_v2.csv`). All provenance-URL backfills and the traffic_scope-aware `traffic_tier` rule are baked into this script (not applied as one-off patches afterward). Also exposes `FIELDNAMES` (now includes `category`/`sub_category`/`as_of_date` plus `schema_extend.EXTRA_FIELDNAMES`, 65 columns total) and `traffic_tier_for()`, reused by `build_a0_phase2.py`. Calls `schema_extend.extend_rows_with_production_schema(rows, start_index=0)` at the end of `build_rows()` and runs all rows through `evidence_harden.harden_rows()` before writing. `SOURCE_URL_OVERRIDES` and inline UNKNOWN-revert tuples now also encode the last pre-950 patch's reviewed KEEP/REVERT decisions for the previously-auto-backfilled C-tier citations.
- `build_a0_phase2.py` — builds the A0-Phase2 40 new-site rows directly in the V2 canonical schema (not a migration -- these are new research entries) and concatenates them with the existing 10 into `validation_50_v2.csv`. All facts/URLs were gathered by dedicated research passes before this script was written; the script only assembles and validates structure (enforces Rule #8, computes `traffic_tier` from `traffic_scope`, checks for column/row-order mismatches and duplicate domains within the batch, excluding `schema_extend.ALL_NEW_FIELDNAMES` from the per-row completeness check since those are only added by the later batch-level `schema_extend` call). Calls `schema_extend.extend_rows_with_production_schema(rows, start_index=10)` and runs all rows through `evidence_harden.harden_rows()` before writing. As of the pre-950 hardening round, `traffic_scope` reflects domain *structure* (content-publisher vs. SaaS/app-mixed vs. subdirectory-estimate), not merely whether a traffic number was found -- see research_protocol_v2.md Section 3-6 -- and `revenue_value` is always either `UNKNOWN` or a single clean structured figure, never descriptive/compound/acquisition text (see Section 7-C item 3). The last pre-950 patch added real D-tier reasoning notes (previously empty) for 5 `own_product`/`course_or_community` fields.
- `run_gate_v2.py` — the Protocol V2 Validation Gate (research_protocol_v2.md Section 7). Accepts an optional CSV path argument; defaults to `../validation_10_v2.csv`. Runs 13 sections (value-requires-evidence directional check, D-tier-requires-note check, `revenue_value` format check, plus -- new in the last pre-950 patch -- `category` enum validation, mandatory ISO `as_of_date`, and `content_scale_proxy_evidence` checks folded into the existing provenance/note/value-requires-evidence/Rule-8 checks) and its final summary line is dataset-neutral (`VALIDATION GATE PASS -- rows=N`).
- `summarize_dataset.py` — automated, dataset-neutral summary generator. Computes row count, `category` distribution (the actual closed-enum field, **not** `primary_niche` -- fixed in the last pre-950 patch; `primary_niche` is now reported separately as free-text reference-only detail with distinct/singleton counts), sampling_stratum/traffic_scope/traffic_tier distributions, `is_contrast_case` counts (kept explicitly separate from `sampling_stratum == "Contrast Cohort"` counts -- these are different axes), per-field UNKNOWN rate and completion rate, and the evidence-tier distribution (with a self-check: `N evidence-bearing fields x N rows` printed alongside the actual count, so an arithmetic mismatch like the earlier hand-written report's "550 vs 500" error is structurally impossible). Replaces all manual/hand-typed aggregation in reports going forward.
- `build_domain_registry.py` — Domain Registry builder/tooling for the future wave-based 950-site expansion. Maintains `research/blog-monetization/registry/domain_registry.csv` (one row per canonical root domain, `status` in {EXCLUDED_PRIOR_PILOT, RESERVED, COMMITTED, REJECTED}). **Hardened into an actually-enforced state machine in the last pre-950 patch**: `IMMUTABLE_STATUSES = {EXCLUDED_PRIOR_PILOT, COMMITTED}` plus a shared `_transition()` helper make `commit_domains()`/`reject_domains()` raise `RegistryStateError` for a domain not in the registry, a domain in an immutable status, a domain not currently `RESERVED`, or a `batch_id` mismatch -- these were previously documented conventions only, not enforced. The seed-time A0/prior-pilot registrable-domain overlap check is now a hard `FAIL`/non-zero exit instead of a `WARNING`. `merge_wave_into_master()` now also checks registrable-domain-based duplicates (`domain_utils.registrable_domain()`) in addition to raw canonical-string duplicates. Currently seeds the 50 A0-cumulative domains as COMMITTED and the prior 100-site pilot's 97 unique domains as EXCLUDED_PRIOR_PILOT via `--pilot-csv` (147 rows total, 0 overlap).
- `wave_coordinator.py` — (new, last pre-950 patch) single-coordinator wave orchestrator for the future 950-site expansion. Only this module is expected to call registry-mutating functions; parallel research workers never touch the registry directly, they only research already-RESERVED domains and hand back plain row dicts. `run_wave()` performs candidate selection → canonicalization → duplicate check → RESERVE → worker dispatch → wave Gate → COMMIT (or leaves domains RESERVED, not REJECTED, on Gate failure, since that's usually a fixable data bug) → merge into the master dataset. `python wave_coordinator.py --demo` exercises the full state machine end-to-end against 3 SYNTHETIC placeholder domains in a temp registry/master file, including verifying that re-committing an already-COMMITTED domain and committing under the wrong `batch_id` both correctly raise `RegistryStateError`. This round performs no real 950-site research -- `--demo` is the only supported CLI mode.
- `test_validation_tooling.py` — regression tests, now **28/28 passing** (12 from the GPT review of commit `40732be`, see research_protocol_v2.md Section 7-B, plus 16 new in the last pre-950 engineering patch covering: non-UNKNOWN-value-requires-evidence, C-tier no-source_url / D-tier empty-note raising, D-tier with a real note passing, `revenue_value` format enforcement, the summary's evidence-cell self-check and its use of `category` over `primary_niche`, the Domain Registry state-machine guards (duplicate reserve, immutable-status transitions, wrong-batch_id commit, registrable-domain merge duplicates), and the intentional Full-PSL known-limitation test for blogspot subdomains).
